## Игровой интерфейс

- Более точный поиск: точное совпадение, начало названия и подстрока выше исправлений опечаток. Хорошая выдача больше не заполняется случайными похожими словами.
- Компактные результаты с постерами, тёмный тонкий скролл, прокрутка активной подсказки при выборе клавиатурой.
- На вертикальном телефоне выдача открывается над полем ввода и не увеличивает высоту страницы. На широком экране поиск расположен рядом с кадром.
- Скелетоны вместо текстовых загрузок; уже открытые кадры берутся из клиентского кеша. Пока новый оплаченный кадр не загрузился, следующая платная подсказка недоступна.
- Убрана видимая буква «с» под таймером, сохранена доступная подпись для скринридера.
- Начальная ширина пиксельной версии увеличена с 24 до 48 пикселей; далее 80, 144, 288, 960. Все стадии сохраняют пропорции исходника; версия серверного кеша изменена.
- В расширенных соло-настройках больше нет одновременно двух комплектов одинаковых переключателей. Выбранный режим ответа и подборка передаются в форму.

## «Раньше или позже»

Локальный адрес: http://localhost:3000/play/chronology (ссылка в «Соло»).

10 пар, без таймера. Год второго фильма скрыт до ответа. Соседние фильмы с одинаковым годом исключены, фильмы в партии не повторяются. Сервер рассчитывает результат; клиент не передаёт год или очки. Повтор команды не начисляет очки повторно, менять ответ после принятия нельзя. Сессия привязана к игроку, ограничена 30 минутами, восстанавливается после перезагрузки страницы. После перезапуска сервера эта отдельная казуальная сессия сбрасывается; рейтинг она не меняет.

## Контент: реальные цифры

По локальному `/api/content/availability` после импорта:

| Категория   | Кадры / Пиксели / Микс | Лупа |
| ----------- | ---------------------: | ---: |
| Фильмы      |                    549 | 1614 |
| Сериалы     |                    125 |  217 |
| Мультфильмы |                    326 |  428 |

Это не 1500 фильмов с кадрами. Цель 1500 достигнута для фильмов с постерами; кадровый пул вырос с 209 до 549. Основной проход кадров подготовил 338 дополнительных фильмов, параллельный штатный импорт добавил ещё два.

Автоматический импорт списка использует метаданные и постеры непосредственно из API. Уже сохранённые метаданные повторно не запрашиваются ради кадров: один отдельный запрос списка изображений на известный фильм. Проверки размера, пропорций и похожести изображений выполняет код. Ручное составление списка фильмов не требуется.

Импорт остановился на HTTP 402 поставщика. Прогресс и блокировка на 24 часа сохранены; повторный запуск до восстановления квоты не должен отправлять запросы. Для продолжения после восстановления квоты:

```sh
docker compose exec -T api sh -c 'cd /app/apps/api && pnpm catalog:grow 1500 600 1'
```

Последние аргументы: цель постеров, бюджет проверки кадров, максимум пакетов списка. Это локальная команда, не публикация. Дальнейший кадровый импорт продолжит недостающие фильмы. Изменение API-ключа учитывается по отпечатку, сам ключ в checkpoint не хранится.

В базе 1616 метаданных фильмов: по 120–195 фильмов в каждом десятилетии с 1930-х до 2020-х, два без года. Доступность режимов считается отдельно от числа записей в базе. Существующая ротация предпочитает не показанные пользователю фильмы и сохраняет историю выбора.

## Стабильность и безопасность

- Закрыты два известных уязвимых транзитивных пакета: body-parser 2.4.0 и multer 2.5.0. Закреплены в overrides и lockfile. `pnpm audit --prod --audit-level high`: No known vulnerabilities found.
- Сжатые тела JSON/form-запросов не принимаются; лимиты размеров сохранены.
- Создание/вход в комнату и ежедневная игра требуют правильный Origin и ограничивают частоту до работы с идентификацией/БД. У нового режима есть ограничения по IP и игроку, строгие схемы команд и лимит активных сессий.
- При временном сбое обновления каталога сохраняется последняя рабочая версия. Холодный запуск без базы не притворяется готовым каталогом.
- Убрана линейная повторная выборка метаданных внутри цикла обновления каталога.
- Автоматическая обработка не переписывает отклонённые права/редакторские статусы. Настройки предпросмотра не изменялись.

## Ограничения перед будущей публикацией

Новые фильмы и исходники находятся только в локальных PostgreSQL/томе Docker, не на Render. Нужен отдельный перенос при разрешённом деплое. Кадры для оставшихся фильмов требуют следующего доступного бюджета API. Текущий локальный каталог изображений занимает сотни МБ; перенос полного растущего каталога в бесплатную БД не следует считать бесконечным хранилищем. Перед публикацией отдельно проверить бюджет медиа и память сервера на целевом тарифе. Это проверка известных сценариев и зависимостей, не полноценный аудит или нагрузочный тест.
