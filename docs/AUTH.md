# Аккаунты и дуэли

Вход по почте и паролю, подтверждение адреса, восстановление пароля и случайная дуэль 1 на 1. Пароль — 10–128 символов. Подтверждение и сброс действуют 30 минут, используются один раз. Сброс пароля отзывает все сессии. Пароли хешируются scrypt с солью; cookie сессии — HttpOnly, SameSite=Lax, Secure на HTTPS, срок 30 дней. В базе хранится хеш токена. Изменяющие запросы проверяют Origin; попытки входа и отправка писем ограничены.

## Локальный запуск

`docker compose up --build -d --wait` поднимает игру и Mailpit. Откройте http://localhost:3000/account, зарегистрируйтесь, затем откройте http://localhost:8025 и подтвердите адрес по ссылке из письма. Mailpit перехватывает письма: они не уходят во внешний почтовый ящик. Для проверки двух игроков используйте разные браузерные профили или обычное и приватное окно.

При запуске API вне Docker укажите доступный SMTP_HOST. По умолчанию SMTP Mailpit доступен только внутри Docker. Для публичного запуска нужны собственный SMTP и HTTPS WEB_ORIGIN; тестовый ящик не является сервисом доставки писем.

## Яндекс и Twitch

Адаптеры реализованы, но для настоящего входа нужно зарегистрировать приложения и заполнить серверный `.env`. Без ключей кнопки отключены. Реальный вход в провайдеры требует отдельной проверки с этими ключами.

- Яндекс: https://oauth.yandex.ru/ — YANDEX_CLIENT_ID, YANDEX_CLIENT_SECRET. Redirect URI: `http://localhost:3000/api/auth/oauth/yandex/callback`. Достаточно базового профиля, можно включить `login:info` для отображаемого имени. Authorization Code + PKCE S256.
- Twitch: https://dev.twitch.tv/console/apps — TWITCH_CLIENT_ID, TWITCH_CLIENT_SECRET. OAuth Redirect URL: `http://localhost:3000/api/auth/oauth/twitch/callback`. Confidential client, Authorization Code. Email не запрашиваем. Пользователь определяется по Twitch ID; токен проверяется через `/validate`.

После изменения `.env`: `docker compose up -d --force-recreate api`. На публичном домене зарегистрируйте соответствующие HTTPS callback URLs и измените WEB_ORIGIN. Секреты не должны иметь префикс NEXT_PUBLIC и не передаются клиенту.

Провайдерские токены используются для входа и не сохраняются. Аккаунты разных провайдеров не объединяются автоматически по email. Привязка нескольких способов входа к одному аккаунту пока не реализована.

Официальная документация: [Яндекс, код подтверждения и PKCE](https://yandex.ru/dev/id/doc/ru/codes/code-url), [Яндекс, профиль](https://yandex.ru/dev/id/doc/ru/user-information), [Twitch, Authorization Code](https://dev.twitch.tv/docs/authentication/getting-tokens-oauth/), [Twitch, проверка токена](https://dev.twitch.tv/docs/authentication/validate-tokens/).

## Дуэли и ограничения

Первая версия: фильмы, кадры, 3 раунда по 45 секунд, без рейтинга. После входа откройте `/battle`. Оба игрока получают одну комнату, одинаковые подсказки и серверный таймер. Старт автоматический после подключения обоих. Посторонние не могут войти по коду. Очередь без опроса истекает через 30 секунд; на подключение после подбора даётся минута. Переподключение сохраняет текущую партию и очки. Выход посреди партии не останавливает таймер соперника.

Аккаунты и сессии сохраняются в PostgreSQL. Комнаты, подбор и ограничители частоты запросов пока живут в одном процессе API: перезапуск сбрасывает активные игры и очередь. Для нескольких реплик нужны общий брокер/Redis и распределённые ограничители. История матчей, рейтинг и объединение аккаунтов — следующие отдельные задачи.

## Проверки

`pnpm check` — типы, линтеры, модульные тесты и сборка. `pnpm test:auth` — интеграция с PostgreSQL в отдельной временной схеме: одновременное использование ссылки, срок/повторное использование, неверный пароль, подтверждение, отзыв сессий и выход. Рабочие аккаунты не затрагиваются.
