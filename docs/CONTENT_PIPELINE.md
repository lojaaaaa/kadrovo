# Каталог: импорт, подготовка и игра

Сервер поддерживает две отдельные подборки: демо и кинокаталог. Выбор доступен при создании комнаты. Кинокаталог включается для конкретных категории и режима, когда опубликованы минимум три разных произведения. Если он пуст или временно недоступен, демо остаётся доступным. Автоматической подмены выбранной подборки нет.

## Что реализовано

- Первый адаптер — ПоискКино v1.5, карточка и изображения. Схема сверена с https://api.poiskkino.dev/documentation-json 22.10.2026. Основной источник выбран по исследованию CONTENT_SOURCES.md; подключение дополнительных провайдеров остаётся отдельным этапом.
- Импорт по ID сохраняет карточку, оригинальное название, русские и альтернативные имена, внешний ID и кандидатов изображений. Повторный импорт не дублирует карточку и не сбрасывает её проверки. У ПоискКино единое пространство ID; внутренний mediaType для него — title.
- Анимация отделяется от игровых сериалов. Кадры допускают типы still/frame/screenshot; promo и shooting не попадают в кандидаты кадров. Backdrop сохраняется как отдельный тип, но не используется как кадр автоматически.
- Игра ищет по локальному каталогу, включая алиасы, ё/е и пунктуацию. Поиск не делает запрос к провайдеру на каждое нажатие клавиши и не ограничен ответами текущей партии.
- Импорт сохраняет ссылки и метаданные, а не одобряет изображения. У каждого asset отдельно rightsStatus и editorialStatus, изначально unreviewed.
- Публикация создаёт пять растровых файлов вне web/public. Для лупы сохраняются только подготовленные кропы; полный постер не передаётся браузеру заранее.
- Каталог перечитывается каждые 30 секунд без перезапуска API. Текущая партия сохраняет свой набор изображений. Снятие публикации/отзыв одобрения исключает загадку из новых партий после обновления; уже запущенный раунд не прерывается.

## Ключ и запуск

Добавить `POISKKINO_API_KEY` в корневой `.env`. Он игнорируется Git и Docker build, передаётся только контейнеру API. Не помещать ключ в `NEXT_PUBLIC_*` и не отправлять в чат.

```sh
docker compose up --build -d --wait
docker compose exec -T api pnpm catalog import poiskkino 258687
```

Одна карточка с постером и одна страница до 50 кандидатов кадров — два запроса. Изображения запрашиваются с фильтром type=frame/still/screenshot: без него первая страница может целиком состоять из фан-арта и концептов. Четвёртым аргументом можно указать 2 или 3 страницы. Пагинация идёт по next; hasMoreImages в отчёте означает, что просмотрены не все результаты. Ошибки API и лимиты не обходятся повторными бесконечными запросами.

Команды ниже выполняются с тем же префиксом `docker compose exec -T api pnpm catalog`:

```sh
list
inspect <titleId>
review <assetId> rights approved "Ссылка на разрешение или документ-основание"
review <assetId> editorial approved
publish /tmp/puzzle.json
unpublish <puzzleId>
```

`rights approved` — фиксация реального основания использования, не автоматическая проверка лицензии. Редактор проверяет принадлежность кадра, узнаваемость, порядок, водяные знаки, название на постере и область раскрытия. Публикация заблокирована, пока оба статуса каждого выбранного изображения не approved и отсутствует основание прав.

Для локальной разработки без контейнера API: `pnpm catalog ...`. В этом случае подготовленные изображения лежат в `.data/content`, а база берётся из `.env`. Не смешивать этот каталог файлов с Docker-volume: контейнер использует свой content_data.

## Манифесты

Сначала получить реальные UUID через inspect. В режиме кадров все пять ID должны быть разными и принадлежать одному произведению; порядок в массиве — порядок показа:

```json
{
  "titleId": "UUID произведения",
  "mode": "frames",
  "assetIds": [
    "UUID кадра 1",
    "UUID кадра 2",
    "UUID кадра 3",
    "UUID кадра 4",
    "UUID кадра 5"
  ]
}
```

Для лупы координаты нормализованы от 0 до 1 относительно повёрнутого по EXIF постера. Каждая следующая область должна целиком включать предыдущую и быть больше. Ниже только пример геометрии — реальный постер нужно просмотреть, чтобы не раскрыть его название:

```json
{
  "titleId": "UUID произведения",
  "mode": "spotlight",
  "assetId": "UUID постера",
  "crops": [
    { "x": 0.45, "y": 0.45, "width": 0.1, "height": 0.1 },
    { "x": 0.4, "y": 0.4, "width": 0.2, "height": 0.2 },
    { "x": 0.3, "y": 0.3, "width": 0.4, "height": 0.4 },
    { "x": 0.2, "y": 0.2, "width": 0.6, "height": 0.6 },
    { "x": 0.1, "y": 0.1, "width": 0.8, "height": 0.8 }
  ]
}
```

Скопировать подготовленный файл в контейнер и опубликовать:

```sh
docker compose cp ./puzzle.json api:/tmp/puzzle.json
docker compose exec -T api pnpm catalog publish /tmp/puzzle.json
```

Для «Микса» у каждого из трёх произведений должны быть опубликованы обе механики. В отдельных режимах достаточно соответствующей механики. Текущая партия — три случайные загадки, вопросы пока могут повторяться в реванше.

## Хранение и ограничения

Миграция 202610220002_puzzles добавляет опубликованные загадки. PostgreSQL хранит метаданные и связи, content_data — приватные WebP-файлы. Обычный `docker compose down` сохраняет оба volume. Для переноса нужны оба хранилища.

Скачивание разрешено только с списка поддерживаемых CDN в images.ts, по HTTPS без переадресаций. Ограничены таймаут, размер файла (10 MB), размер декодируемого изображения (40 MP) и число страниц API. SVG/HTML и анимация не допускаются. Новый CDN добавляется осознанно после проверки, произвольный proxy URL отсутствует.

Кеш прототипа ограничен 5000 названий, 120 опубликованными механиками и 50 MB подготовленных файлов. До увеличения каталога нужны пагинация/поиск в базе и адресное хранение изображений. Старые версии растров после перепубликации сохраняются; автоматическая сборка неиспользуемых файлов ещё не сделана. Веб-редактор и массовый импорт пока не реализованы: управление доступно локальной CLI.

## Проверки

`pnpm test` включает парсер, категории, пагинацию, отсутствие ключа, ограничения загрузки и геометрию кропов.

`pnpm test:content` использует отдельную случайную схему PostgreSQL и временную папку. Проверяет идемпотентность импорта, блокировку до одобрения, публикацию, сохранность в базе, русский поиск по алиасам, запуск партии из опубликованного каталога и отзыв изображения. Изображения генерирует сам тест; сеть провайдера не вызывается. После теста его схема и файлы удаляются.

## Локальная игровая подборка

Для локального просмотра включён `LOCAL_CONTENT_PREVIEW=true` в `.env`.
Флаг передаётся контейнеру API и действует только при loopback-адресе WEB_ORIGIN
(localhost, 127.0.0.1, ::1). Без флага или с публичным WEB_ORIGIN каталог требует
одобренных прав и основания, как раньше. Отозванные материалы исключаются в
обоих режимах; редакторское одобрение обязательно. Флаг не изменяет статусы прав
и не является подтверждением лицензии. При внешнем развёртывании отключить флаг.

Первая локальная подборка: «Интерстеллар», «Матрица», «Титаник» — по пять
просмотренных кадров в режиме «Кадры». Порядок выбран редакторски, сложность ещё
нужно проверить на игроках. Файлы публикуются в Docker-volume content_data.
«Лупа», «Микс» и другие категории пока не имеют готового игрового набора.
Новые комнаты автоматически предпочитают доступный кинокаталог; явно выбранная
пользователем подборка сохраняется. Существующая демокомната остаётся демо.

Проверка локальной подборки: в браузере создана комната с автоматически выбранным
кинокаталогом, подключён второй тестовый участник, показан реальный WebP-кадр.
Поиск «интерстелар» нашёл «Интерстеллар», стрелка и Enter выбрали подсказку без
отправки. Нажатие «Ответить» начислило 562 очка; таймер продолжил работу.
Сетевой клиент подтвердил demo=false и отсутствие ответа в публичном снимке.

## Подборки и расширение каталога (23.10.2026)

Команда `pnpm catalog import-list /absolute/path/ids.json` импортирует JSON-массив числовых ID ПоискКино, до 500 за запуск. Дубликаты ID пропускаются; повторный импорт обновляет существующие записи. На произведение используются карточка и одна страница кандидатов; при ошибке выполнение останавливается, ранее импортированное сохраняется. Команда не публикует изображения и не подтверждает права/редактуру. Начальный дополнительный список: `content/starter-titles.json`.

Подборки: весь каталог, до 1990 года, 1990-е, 2000-е, 2010-е, с 2020 года. Границы включительные; неизвестный год допускается только в общую подборку. Счётчики в `/content/availability` отражают опубликованные загадки отдельно по категории и режиму. Выбор доступен при наличии минимум трёх произведений. Лобби синхронизирует выбор через `room:settings`; смена настроек сбрасывает готовность. В батле всегда используется весь доступный каталог фильмов с кадрами; три разных произведения выбираются сервером случайно, без повторов внутри партии. Между разными партиями повторы возможны.

Текущая локальная подборка кадров расширена с 9 до 27 произведений: 21 фильм и 6 анимационных. Для новых произведений лупа ещё не подготовлена; её счётчик остаётся отдельным. Из дополнительного списка 19 произведений 18 опубликованы после просмотра контактных листов, «Хороший, плохой, злой» оставлен для дальнейшего отбора. Статусы прав не менялись, действует ранее включённый режим локального предпросмотра.

Предел загрузки повышен до 2000 опубликованных загадок и 250 МБ подготовленных файлов на обновление. Это временный ограниченный кеш в памяти, не архитектура для миллионов изображений. Перед ростом сверх этого объёма требуется выдача подсказок по защищённым URL с загрузкой файлов по запросу вместо хранения всего в base64. Текущее расширение не импортирует всю внешнюю базу и не выполняет фоновую синхронизацию.

## Автоматическая подготовка кадров

`docker compose exec -T api pnpm catalog sync-auto 50` получает до 50 популярных фильмов из ПоискКино (сортировка по числу голосов), импортирует карточки и кандидаты кадров, затем автоматически публикует пригодные наборы. Допустимо 1–200 за запуск. Увеличение числа расширяет выборку; уже опубликованные фильмы пропускаются, ручные подборки не перезаписываются. Это запускаемая команда, не фоновое расписание.

Для нового фильма проверяются до 50 кандидатов типа still/frame/screenshot: HTTPS из разрешённого CDN, допустимый статичный растровый файл, размер минимум 480×240, горизонтальные пропорции, отличие perceptual dHash от уже выбранных кадров. При наличии пяти разных пригодных изображений создаются пять подсказок. Если их меньше — фильм остаётся в поиске названий, но не попадает в раунд. Ошибка API/квота останавливает импорт без бесконечных повторов. Результаты завершённых фильмов сохраняются.

Машинный отбор получает отдельный editorialStatus=automated, а не отметку ручной проверки. Публикация принимает ручной approved и automated. Статусы прав и режим локального предпросмотра не изменяются. Это техническая проверка: порядок сложности, отсутствие текста и семантическая принадлежность кадра полностью автоматически не гарантируются. Редактор может отклонить плохой кадр; загадка будет исключена из новых игр при обновлении кеша. Лупа пока использует подготовленные ранее области постеров: автоматическое обнаружение текста на постерах не реализовано.

Таким образом внешний API остаётся источником фильмов и кадров. Наша база и файлы — кеш для стабильной игры, поиска, приватных подсказок и ограничений квоты, а не ручное повторение внешнего киносправочника.

Первый автоматический запуск 23.10.2026: проверено 50 популярных фильмов, 12 уже были опубликованы, 35 добавлены автоматически, 3 не набрали пяти подходящих кадров. Локальный итог: 56 фильмов с кадрами и 6 мультфильмов; лупа остаётся у прежних 9 фильмов. Это фактический результат запуска, а не обещание полного покрытия API.

## Фоновое пополнение Кадрово

В Docker включён CONTENT_AUTO_SYNC (можно отключить значением false). Сервер раз в 8 часов обрабатывает следующую страницу из 20 произведений, по очереди movie, tv-series, cartoon. При максимуме двух запросов на новое произведение это около 123 запросов в сутки без ручных запусков; квоты поставщика могут отличаться. Позиция и время последней попытки сохраняются в content_data/sync-state.json. После ошибки нет немедленных повторов, следующий цикл не раньше 8 часов. Это однопроцессный worker для текущей установки с одним API; перед несколькими репликами нужен распределённый lock/очередь. Ручные импорты тоже расходуют квоту.

`pnpm catalog sync-auto 100 movie`, `pnpm catalog sync-auto 20 tv-series`, `pnpm catalog sync-auto 20 cartoon` позволяют отдельно расширять категории. Пользователь не ждёт обращения к внешнему API в середине раунда. Каталог автоматически обновляется после подготовки материалов.

Режим pixels доступен для каждого набора кадров: первый кадр преобразуется сервером в пять уровней детализации. Браузер получает только текущую подсказку, исходник заранее не выдаётся. Сгенерированные уровни кешируются по версии опубликованной загадки; при снятии публикации кеш очищается при обновлении.

## Автоматическое наполнение из API

Рабочий альтернативный источник — `KINOPOISK_UNOFFICIAL_API_KEY` (передаётся в API-контейнер). Каталог и пагинация: `/api/v2.2/films`, кадры: `/api/v2.2/films/{id}/images?type=STILL&page=1`. Постеры берутся из карточки произведения. Фильтр сериалов — `TV_SERIES`, мультфильмов — жанр 18 из справочника провайдера. Результаты двух источников объединяются по общему ID Кинопоиска.

`pnpm catalog sync-unofficial 20 movie 2` импортирует вторую страницу фильмов; `tv-series` и `cartoon` — соответствующие категории. Провайдер отдаёт 20 карточек на странице. Сервер сам скачивает подходящие изображения, убирает дубли кадров и готовит подсказки. Постеры автоматически превращаются в пять вложенных областей раскрытия. `pnpm catalog auto-posters` дополняет «Лупой» уже импортированные произведения; тот же проход запускается при старте API.

Фоновый импорт каждые 2 часа получает до 200 карточек за несколько страниц, по очереди переключаясь между фильмами, сериалами и мультфильмами. Метаданные и постеры сохраняются сразу для всего пакета; до 10 произведений из очереди ожидающих кадров обрабатываются отдельно. Очередь идёт от давно не обработанных к новым, поэтому предыдущие пакеты не забываются. Позиция пагинации сохраняется отдельно для каждого источника. При HTTP 401/402/403/429 проход прекращается и сохраняется пауза на 24 часа. Смена ключа снимает паузу при следующем цикле. Текущий ПоискКино на проверке 23.10.2026 ответил 403, Unofficial — 200. Ключи никогда не отправляются клиенту.

Это автоматический кэш API, а не ручной набор фильмов: новые ответы провайдера становятся игровым контентом после машинной проверки изображений. Проверки доступности, растрового формата и различимости кадров нужны, чтобы игра не показывала сломанные или одинаковые подсказки. Учёт прав остаётся отдельным от автоматической подготовки.

## Большой каталог и редкие повторы

Список `/films` ограничен сотней результатов на конкретный запрос. Обход расширен: TOP_250_MOVIES, затем интервалы по пять лет с отдельной пагинацией для фильмов, сериалов и анимации. Курсор имеет вид `v2:раздел:страница`; после последней страницы переходит к следующему интервалу. Размер импорта до 200 означает несколько страниц, а не одну. Метаданные из ответа списка повторно используются при импорте: отдельный запрос карточки не нужен, остаётся запрос кадров. CLI сохраняет следующий курсор для фонового продолжения.

Каталог больше не хранит все картинки в виде base64 в оперативной памяти. Вопросы содержат непрозрачные ссылки на файловый кэш, сервер отдаёт только запрошенное изображение. Токены изображений подписаны секретом процесса и не содержат ID фильма или номера следующего кадра. Пиксельные подсказки создаются по запросу, кэш ограничен 64 изображениями. Лимиты индекса повышены до 15 000 названий и 20 000 опубликованных загадок; проверка доступности исходных ассетов выполняется одним запросом.

Выбор фильмов учитывает сохранённую последовательность показов: сначала ещё не показанные, затем наименее недавно использованные; случайный порядок применяется при равной давности. История общая для режимов и пересекающихся подборок, хранится в `rotation.json` в том же Docker-томе. Изменения настроек и предварительная проверка батла не расходуют историю. При маленьком пуле или партии длиннее пула повторы неизбежны; они начинаются после исчерпания доступных фильмов. История относится к одному серверу, а не персональному аккаунту; для нескольких API-инстансов потребуется общее транзакционное хранилище ротации.

Игровой пул исключает релизы с годом в будущем и очевидные анимационные сборники серий/эпизодов. Самостоятельные продолжения фильмов остаются отдельными произведениями. При сетевом разрыве или таймауте запроса к Unofficial допускается один повтор; HTTP-ошибки доступа и квоты не повторяются. Для долгих загрузок можно использовать `docker compose run --rm --no-deps api pnpm catalog ...`: такой импорт не прервётся при пересоздании основного API-контейнера.

На проверке массового импорта API Unofficial вернул HTTP 402 с сообщением о дневной квоте 500 запросов. Дальнейшие запросы остановлены. Очередь, курсоры и уже сохранённые произведения остаются в Docker-томе. Проверка нового алгоритма отдельно подтверждает: все метаданные списка сохраняются до запроса кадров, поэтому исчерпание квоты на кадрах не теряет каталог и постеры.
