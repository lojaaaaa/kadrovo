# Источники Filmless: решение от 23.10.2026

## Решение

Основной импорт — ПоискКино: русские и альтернативные названия, год, тип, внешние ID, постеры и кандидаты кадров. Kinopoisk API Unofficial — дополнительный источник для произведений, которым не хватает подходящих кадров. TMDB пока не обязательная зависимость: подключать для конкретных пробелов в постерах и сериалах после сравнительной проверки.

Это выбор для следующего этапа разработки, а не подтверждение прав на публичное использование всех изображений. ПоискКино и Kinopoisk API Unofficial — сторонние поставщики; их не следует представлять как официальный API Яндекса.

## Почему в игре мало фильмов

Внешняя карточка, импортированное произведение и опубликованная загадка — разные состояния. Текущий адаптер импорта реализован для ПоискКино; наличие ключа Unofficial само по себе не добавляет его изображения в игру. Для расширения нужны массовый отбор произведений, загрузка кандидатов, редакторская проверка и публикация. Миллион карточек у поставщика не означает миллион готовых загадок.

Для кадров: пять разнообразных изображений, подтверждённая принадлежность фильму, порядок от менее очевидного к более узнаваемому. Не принимать съёмочную площадку, рекламу, фан-арт и почти одинаковые дубли. Для лупы: один постер и пять вложенных областей раскрытия, которые не выдают название текстом. Для сериалов ответ остаётся названием сериала, даже если кадр пришёл из эпизода.

## Организация каталога

1. Каталог ответов хранит русские названия, алиасы и внешние ID, включая произведения без готовых загадок. Это делает поиск естественным и не превращает короткий список ответов в подсказку.
2. Игровой каталог содержит только подготовленные загадки; доступность считается отдельно для кадров и лупы. Для микса нужен подходящий набор обеих механик.
3. Источники используются во время импорта; игровые запросы и поиск не обращаются к ним напрямую.
4. Подготовленные изображения хранятся в собственном хранилище при наличии разрешения на такое использование. В браузер выдаётся только открытая подсказка.
5. Хранить происхождение, внешние ID, подтверждения использования и связь каждого изображения с загадками. Снятие материала должно исключать связанные загадки из новых игр.

## План наполнения

Первый измерительный этап: 45 произведений — по 15 фильмов, сериалов и анимационных произведений, с российским и зарубежным контентом, разными десятилетиями. Считать долю произведений с пятью пригодными кадрами, с пригодным постером, время редактора на загадку и число запросов. Только после этого решать, нужен ли постоянный второй поставщик.

Целевой первый выпуск (предложение, не текущая готовность): 150 произведений — 90 фильмов, 30 сериалов и 30 анимационных. Если все доступны в двух механиках, это 750 отобранных кадров и 150 постеров; подготовленные кропы лупы считаются отдельно. Сначала качество этого набора, затем расширение до 300–500.

Нужен редактор каталога: очередь кандидатов, фильтры категории/источника, контактный лист кадров, выбор и порядок пяти подсказок, редактор кропов, предпросмотр и публикация. Автоматизация помогает импортировать, искать дубли и проверять размеры, но не подтверждает принадлежность и игровую сложность.

## Тарифы и условия

На [сайте ПоискКино](https://poiskkino.dev/) проверены: demo 200 запросов/сутки; базовый 5 000/сутки за 2 500 ₽/мес; заявленный безлимит за 5 000 ₽/мес. Для иллюстрации: 150 произведений × (карточка + одна страница изображений) = 300 запросов без поиска, повторных страниц и обновлений. Это расчёт нижней границы запросов, а не бюджета подготовки каталога. Стоимость труда и хранения сюда не включена.

У [Unofficial](https://kinopoiskapiunofficial.tech/documentation/api/openapi.json) подтверждён endpoint STILL и ограничение 25 запросов/сек; текущую цену и дневной лимит следует брать из личного кабинета, в этой проверке они не установлены.

[TMDB Movie Images](https://developer.themoviedb.org/reference/movie-images) отдаёт posters/backdrops/logos; backdrop нельзя автоматически считать настоящим кадром. [Episode Images](https://developer.themoviedb.org/reference/tv-episode-images) полезен для сериалов. [FAQ TMDB](https://developer.themoviedb.org/docs/faq) требует атрибуцию, для коммерческого проекта — отдельное согласование; TMDB не заявляет владение всеми изображениями.

Оплата доступа к API сама по себе не устанавливает права на коммерческий показ, хранение и обрезку конкретных изображений. До публичного запуска получить условия именно для веб-игры: показ кадров и постеров, собственное хранение/CDN, преобразование в подсказки, территория, монетизация, атрибуция и удаление. Если поставщик не даёт нужных прав — нужны отдельные разрешения правообладателей/дистрибьюторов. Не выставлять rightsStatus=approved на основании работающего ключа.

[Flim](https://flim.ai/terms-and-conditions), раздел 4, запрещает стандартными условиями развлекательное использование и перепубликацию изображений; обычная подписка не подходит для нашей игры. Пресс-материалы также проверять по конкретным условиям предоставления. Самостоятельное извлечение кадров из видео не решает вопрос разрешения.

## Что не проверено

Покрытие российских произведений; качество всей выборки; доступность CDN из нескольких российских сетей и будущего хостинга; TMDB с авторизованным ключом; договорные права поставщиков на нужное использование. Новые загадки в рамках этого исследования не публиковались.
