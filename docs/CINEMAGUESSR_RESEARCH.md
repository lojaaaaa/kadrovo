# CinemaGuessr: исследование и направление для Кадрово

Дата: 24.10.2026. Изменения только локальные, без GitHub и деплоя.

## Как проверено

Изучены публичная страница [режимов](https://cinemaguessr.ru/modes), её подключённые CSS, шрифты и клиентский JavaScript. Код прочитан как текст, не исполнялся. Дополнительно проверен публичный [ответ категорий](https://cinemaguessr.ru/api/v1/game/categories). Из маршрутизации и компонентов разобраны основные разделы ниже.

Управление браузером отключено настройками Work. Поэтому это исследование структуры, оформления и заданного поведения, **не отчёт о прохождении всех сценариев в браузере**. Вход, реальная партия, мобильная отрисовка и субъективная плавность требуют отдельного просмотра. Наличие компонента не доказывает работоспособность серверной функции. Например, Duel в текущем клиенте помечен как недоступный.

## Карта основных разделов

| Раздел                   | Что подтверждено публичным клиентом                                                | Вывод для нас                                                                                                           |
| ------------------------ | ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `/`                      | Кинематографическая заставка, фоновые кадры, одно главное действие                 | Атмосферу можно передать декоративной графикой. Длинную заставку возвращать не стоит: пользователь уже просил убрать её |
| `/modes`                 | Четыре направления, карточки с иллюстрациями и разными оттенками; Duel пока закрыт | Выбор становится понятнее, когда у направления собственный визуальный образ, а не только одинаковая иконка              |
| `/game`, `/categories`   | Отдельный выбор категории, число доступных произведений и обработка пустого списка | Показывать фактическое наполнение полезнее, чем обещать огромный каталог                                                |
| `/game/:category`        | Тематическая страница с объяснениями и входом в игру                               | Для постоянного игрока такие страницы лучше обходить прямым запуском                                                    |
| Игровой экран            | Разные способы ответа, последовательные подсказки, итог с разбором                 | Разделять состояние «думаю», «ответ принят» и «жду остальных» важнее декоративных эффектов                              |
| `/party`, `/party/:code` | Приглашение, готовность, настройки, чат, исключение игрока и состояния соединения  | Настройки должны жить в лобби, а игра — показывать кадр, ответ, время и участников                                      |
| `/leaderboard`           | Категории, выделение лидеров и своей строки, раскрываемые подробности              | Повторяемые строки легче читать, если место, имя и результат всегда стоят на одной оси                                  |

| `/about`, `/privacy`     | Объяснение правил и происхождения данных                                           | Мы тоже должны понятно объяснять источники контента и смысл очков, но вне основного игрового поля                       |

Категории в проверенном API: общий пул — 1554, зарубежные — 823, сериалы — 314, российские/советские — 187, мультфильмы — 137, аниме — 78, топ — 250. Это пересекающиеся подборки: **складывать эти числа нельзя**. Это значения ответа API на дату проверки, не независимая проверка каждой загадки.

## Из чего складывается стиль

**Тёмный фон имеет оттенок.** В CSS используются графит `#0a0c0f`, поверхность `#14171c`, приподнятая поверхность `#1c2027`, границы `#262b33`. Это позволяет разделять слои без крупных теней. У нас предыдущая переменная фона уже была изменена, но в `body` оставался жёстко заданный чёрный цвет — он исправлен.

**Цвет помогает ориентироваться.** Тёплый светлый, зелёный, янтарный и другие тона распределены между направлениями и состояниями. Наше решение: оставить узнаваемый оранжевый в бренде, но не заливать им все поверхности и действия. Для Соло — приглушённый тёплый оттенок, для Онлайна — холодный зелёный; ошибка по-прежнему красная.

**Типографика делит задачи.** В шрифтах конкурента объявлены Manrope, Unbounded и JetBrains Mono. Важно не копирование гарнитур, а контраст ролей: выразительный заголовок, спокойный основной текст, моноширинные служебные подписи и цифры. В Кадрово сейчас использованы системные шрифты без новой сетевой зависимости; служебная подпись стала моноширинной.

**Карточки содержат композицию.** Иллюстрация выходит за край, текст имеет ограниченную ширину, действие находится рядом с содержимым. Пустой прямоугольник не становится интереснее от увеличения высоты. Поэтому для нашей главной сделаны собственные абстрактные кинокадры в SVG; изображения и иллюстрации конкурента не перенесены.

**Размер зависит от задачи.** У страницы режимов в CSS ограничение ширины 980 px и базовая минимальная высота карточки 190 px. У остальных разделов другие ограничения. Не нужно делать каждую страницу одинаковой сеткой на весь Full HD.

## Разбор анимаций

Параметры ниже прочитаны в CSS. Условия медиазапросов могут заменять их; это не измерения записи экрана.

| Элемент             | Заданное поведение                                                                 | Как применяем идею                                                                                          |
| ------------------- | ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Карточка режима     | Наведение около 300 мс, небольшой рост; иллюстрация отдельно движется около 400 мс | У нас подъём на 3 px, плавная граница и лёгкое смещение собственной графики; только для точного указателя   |
| Меню                | Появление около 220 мс с opacity/scale                                             | Выпадающие элементы должны появляться у своего источника, не пересобирать всю страницу                      |
| Игровые панели      | Вход около 760 мс с размытия и подъёма                                             | Для нашей частой игры это долго: выбраны 420 мс для главной, короткие задержки 55/110 мс                    |
| Смена изображения   | Круговое раскрытие около 650 мс; отдельный сдвиг около 220 мс                      | В нашей текущей реализации оставлено короткое появление после загрузки. Длинное раскрытие мешало бы таймеру |
| Табличные строки    | Вход около 450 мс, задержка по индексу                                             | Эффект допустим при первом открытии списка, но не на каждом обновлении живого счёта                         |
| Кнопки              | Плавная заливка/граница около 300 мс, смещение при нажатии                         | Общие кнопки получили явные переходы нужных свойств, без анимации размеров                                  |
| Уменьшение движения | Отдельные правила reduced motion                                                   | Отключены вход, декоративный сдвиг и анимации наведения в соответствующей настройке системы                 |

Чего избегаем: бесконечно прыгающих стрелок, постоянного пульса всех кнопок, размытия всего экрана, повторного появления карточек на каждый сетевой ответ. Это создаёт шум и делает игру медленнее на слабых телефонах.

## Почему прежняя главная не работала

В нашей CSS были `min-height: 100svh`, `flex: 1` у сетки и растяжение строк. На скриншоте высота четырёх панелей близка к 680 px, хотя полезного содержимого существенно меньше. Дополнительно `margin-top: auto` раздвигал иконку и название. Все направления выглядели одинаково важными, а ежедневная загадка получила огромную кнопку внутри пустой площади.

Исправлять это ещё одним ограничением высоты недостаточно: нужна иерархия действий. Пользователь сначала выбирает между одиночной и сетевой игрой. Собственное лобби и ежедневная загадка — другие, менее частые намерения.

## Три варианта главной

### A. Два направления и компактные строки — реализовано

```text
Небольшой заголовок
[ Соло: описание, действие ] [ Онлайн: описание, действие ]
[ Своя комната                           Открыть лобби → ]
[ Фильм дня                                     Угадать ]
```

Два основных направления читаются сразу. Своя комната и ежедневная игра остаются доступными без больших плиток. На широком экране весь модуль занимает примерно 450–500 px по высоте с учётом отступов; точное значение зависит от шрифта и ширины. На телефоне карточки идут последовательно. Никакой искусственной растяжки до нижней границы окна.

### B. Компактная витрина

```text
[ Соло ] [ Онлайн ] [ Своя комната ]
[ Фильм дня: короткая подпись                     Угадать ]
```

Самый быстрый обзор всех возможностей, хорошо работает на широком экране. Минус: три равноправных действия снова заставляют выбирать между обычным онлайном и комнатами. Подходит, если кастомные игры станут основным сценарием.

### C. Один центр запуска

```text
[ Соло | Онлайн ]
Режим / категория (только при необходимости)
[ Играть ]
Своя комната · Фильм дня
```

Самый компактный путь для постоянного пользователя с запомненными настройками. Минус: часть возможностей спрятана за переключателем, состояние необходимо ясно сохранять. К нему можно перейти, когда станет понятно, какой запуск выбирают чаще. Сейчас не добавляем второй параллельный механизм запуска поверх существующих страниц.

## Что сделано сейчас и что проверить дальше

Реализован A: самостоятельная композиция, собственная графика, более низкие карточки, две строки вторичных действий, спокойные оттенки, появление с небольшим смещением и задержками. Маршруты и игровая логика сохранены. Лишние разделы на главную не возвращены. Смена игровой картинки запускает короткое появление после загрузки, а не на каждом тике таймера.

Ручная проверка нужна на 1920×1080, 1366×768, планшете 768×1024, телефонах 390×844 и 360×640, при масштабе 200% и reduced motion. Проверять переносы текста, доступность действий с клавиатуры, отсутствие горизонтального скролла и повторных анимаций при обновлениях. Не обрезать содержимое на маленьких экранах ради формального отсутствия прокрутки.
